# Requirements traceability (glasses perception slice)

Requirement numbers and wording are taken from the comments of the Group 29
radar modules and the Week 6 design review (statechart 6.6). Check them
against the latest report before submission. "Target" = to be measured on the
Pico, not yet done.

| Req | Short text | Code symbol | Test |

| FR13 | **MET, reported per lane, as of OPEN-25 (14 Nov).** Was: closing speed and TTC to BLE, departing targets ignored. OPEN-22 removed all per-target velocity tracking (MIO selection, collision prediction, track IDs, departing filters) as part of the lane-occupancy redesign, leaving ttc_ms always RTE_TTC_NONE_MS. OPEN-23 restored it scoped to a single picked lane (whichever drives d_mm); OPEN-25 dropped that scoping - the nearest lane by distance is not always the one closing in soonest, so a single-lane TTC could silently hide a farther, faster-closing lane's risk. rte_ble_obstacle_t now carries d_mm[3]/ttc_ms[3] (indexed by rte_cue_side_t), one pair per lane: a BLOCKED lane's ttc_ms is computed from its own live, per-frame speed_cms this frame (threat_assessment_closing_cms/_ttc_ms, via the new threat_assessment_lane_out) - never from frame-to-frame position tracking, so OPEN-17's head-motion hazard is not reintroduced; a lane that is not BLOCKED reports RTE_LANE_NONE_MM/RTE_TTC_NONE_MS, and a BLOCKED lane with no live reading this frame (only inside its hold-grace window) reports a real distance but RTE_TTC_NONE_MS. Departing targets are still never excluded from occupancy (OPEN-22, unchanged) and still never given an early-clear exception (considered and rejected in OPEN-23 - a false negative is worse than a nuisance alarm for this user). This is a wire-format change (flagged per OPEN-1/OPEN-12 for BLE-owner sign-off, not finalised). **OPEN-26 (18 Nov):** bench evidence showed the LD2450's own speed_cms flickering unusable for a frame or two even mid-approach, so ttc_ms now also passes through threat_assessment_hold_closing() first - the last usable closing speed for that lane is reused for up to THREAT_ASSESSMENT_LANE_HOLD_MS (200 ms, same window as the existing occupancy hold) before falling back to RTE_TTC_NONE_MS; a lane with no live target at all this frame is unaffected (still immediate RTE_TTC_NONE_MS, unchanged from OPEN-23/25). | threat_assessment_closing_cms, threat_assessment_ttc_ms, threat_assessment_hold_closing, threat_assessment_pick_lane, threat_assessment_scan_lanes, threat_assessment_lane_out, rte_ble_obstacle_t, rte_write_ble_obstacle | test_threat_assessment (closing_cms, ttc as pure utilities; test_ttc_uses_live_speed_of_its_own_lane, test_ttc_is_none_while_the_lane_is_only_held, test_ttc_is_none_for_a_departing_target, test_ttc_holds_a_brief_speed_dropout, test_ttc_drops_to_none_once_the_speed_hold_expires, test_ttc_hold_does_not_resume_across_a_full_occupancy_gap, test_process_frame_sends_audio_and_ble end to end, now checking all three lanes); test_alert_pipeline (test_person_walks_up_alert_starts_then_clears) |
